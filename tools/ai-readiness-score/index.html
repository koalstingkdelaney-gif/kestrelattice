What this checks — and where it comes from

Every question maps to a control in the Governed Agent Mesh Playbook, the system ghostcorpnet runs its own agent fleet under:

  • Identity & authority (Playbook §3): each agent gets its own named identity, scoped permissions, and a revocation path that takes minutes, not a password reset on a shared account.
  • Approval gates (Playbook §4): risky actions — money, customer contact, production changes — pass a human gate above thresholds set in advance, enforced in the call path where code can refuse, not in a prompt the agent can argue with.
  • Spend limits (Playbook §5): hard per-agent budgets and rate caps that halt the agent automatically, plus a kill switch a human can actually reach.
  • Audit trails (Playbook §6): a durable, append-only record of what each agent did — the actual request, the time, and whose approval it ran under — so any day can be reconstructed from records alone.
  • Fail-closed behavior & testing (Playbook §7): when a check fails or the agent is unsure, the default is stop and escalate — and the agent is adversarially tested before production and after every change.

This is a self-check, not an audit: it scores what you tell it. If you scored yourself generously, the honest score is lower — and the weakest-area list is still the right order to fix things in.
