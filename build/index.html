The Pack Standard v1

A pack is a versioned bundle of agent-governance content that any tool — ours or yours — can read and verify. The full spec lives in the repo; this is the working summary.

Anatomy

my-pack/
├── pack.json   manifest
├── README.md   what & who
├── LICENSE      license file
└── policies/    ≥1 artifact

Required files

  • pack.json manifest (validated)
  • README.md — plain-language summary
  • LICENSE file matching the manifest license
  • At least one governance artifact — a PDF (pack.pdf by convention): playbook, checklist, runbook, or worksheet

Versioning

  • Packs use semver: MAJOR.MINOR.PATCH
  • Major = breaking change; minor = new content; patch = fixes
  • requires_standard declares the supported standard range (e.g. >=1.0)
  • Tooling refuses mismatched packs and says so plainly

Integrity

  • Every pack carries a sha256 checksum of its contents
  • Directory verifies it on submission — mismatch rejects the listing
  • Re-compute per version; checksums are per-version

The manifest: pack.json

Every pack declares itself in one JSON file. The v1 baseline schema: manifest_version, standard ("ghostcorpnet-pack/1.0"), name (kebab-case slug), title, version, builder (studio, kind, url), license, artifacts (each: path + kind + title), requires_standard.

{
  "manifest_version": 1,
  "standard": "ghostcorpnet-pack/1.0",
  "name": "agent-spend-guardrails",
  "title": "Agent Spend Guardrails",
  "version": "1.0.0",
  "builder": {
    "studio": "ghostcorpnet",
    "kind": "ghostcorpnet-fleet",
    "url": "https://koalstingkdelaney-gif.github.io/kestrelattice/directory/"
  },
  "license": "CC-BY-4.0",
  "artifacts": [
    { "path": "pack.pdf", "kind": "playbook",
      "title": "Agent spend guardrails playbook" },
    { "path": "schemas/budget.schema.json", "kind": "schema",
      "title": "Budget envelope schema" }
  ],
  "requires_standard": ">=1.0"
}

Badge rules

Two badges, two different meanings. Neither implies partnership with, endorsement by, or revenue sharing with GhostCorp.

Compatible with ghostcorpnet

Meaning: the pack validates against Pack Standard v1 and follows its content rules.
Who may use it: anyone whose pack passes validation — no permission needed, no fee. Self-asserted; the directory independently verifies.

Built on ghostcorpnet

Meaning: the pack passed the certification checklist below plus a human review.
Who may use it: only authors who completed certification and received the licensed badge files. Misuse means removal from the directory.

Certification checklist

To earn the licensed Built on ghostcorpnet badge, a pack must clear every item:

  1. 1Valid manifest — pack.json passes every validation rule (fields, name format, all section paths exist and are non-empty).
  2. 2Real license — a LICENSE file at the pack root, and the manifest license field matches it.
  3. 3Complete README — what the pack covers, who it's for, how to use each artifact, prerequisites.
  4. 4Working examples — every schema validates sample data; every template has its blanks clearly marked.
  5. 5Checksum matches — the manifest checksum reproduces from the pack contents.
  6. 6Honest content — no invented partnerships, stats, or claims; no executable code in required artifacts.
  7. 7Human review — a coordinator reviews the pack for quality and rule compliance before badge files are issued.
Certification is a self-serve checklist. The licensed badge files are issued per pack version after review. Certification of packs will be available as a guided product soon.
